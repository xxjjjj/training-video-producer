# 制作流程与质量规则

## 资料与教学设计

先回答：给谁看；看完要能做什么；用哪个具体案例解释；每章交付什么。目标时长、章节数和固定视觉风格来自本项目需求，不继承其他课程参数。

列出来源文件与权威旁白。有文档内嵌表格占位符但未读表格时，标记未读部分，不能当空白处理。来源冲突时列出原文与位置，先继续不受影响的镜头。

有定稿时保持完整；只有资料时先写草稿，再形成经确认的旁白基线。不要为了填满目标时长加无关内容，也不要为了缩短视频擅删旁白。计划时长和实测配音时长分别记录。

按镜头目的选择画面，不限于以下六类：

| 类型 | 观众应看见的变化 |
| --- | --- |
| 开场案例 | 一份真实输入带出具体任务 |
| 流程链路 | 操作前后数据状态及交给下一步的东西 |
| 边界/风险 | 触发条件、被阻止动作、允许继续的条件 |
| 概念解释 | 具体字段、表格行或结构如何关联 |
| 人工确认 | 候选项、依据、选择后的结果 |
| 总结收束 | 已得到的产物以及下一步用途 |

操作培训优先展示可辨认的工作表、文件、字段或界面状态。简化演示界面与真实产品操作录屏应区分，不得把虚构按钮或流程声称为实测。

## 小样片

选少量有代表性的镜头，覆盖至少一个实质变化/判断、一个长字幕或复杂布局。复用已确认音色和风格；缺少真实配音时可以做明确标识的布局预览，不能称为声音已验收。

检验：声音听感、旁白内容、中文字体、字幕完整、画面清晰、动作是否解释了因果、播放是否流畅。先交付可审阅样片；取得或复用适用确认后扩展生产。

## 配音与时间轴

使用当前镜头的权威旁白。每镜头记录原文指纹、供应商、声音、模型与速度配置、请求标识（如有）、音频文件指纹及实测时长。修改文本或声音配置后，旧音频标记过期；修改布局不用重新配音。

文件名相同、时长合理仍可能内容错误：试听或转写并对照原文。转写仅用于核验，不覆盖原文；姓名、数字、术语需人工复核可疑差异。没有内容验证手段时写 NEED_CONFIRM，不能默认为通过。

请求失败先判定是提交失败、状态未知还是产物下载/转码失败。有任务标识先查原任务，避免重复付费提交；恢复已有音频/WebM 优先于重做。重试受服务约定与当前授权范围约束，不无限循环。

声音选定且本批旁白定稿后，先完成本批配音、内容核验及字幕时间，再 prepare 并编写正式动画；全课已授权时通常一次完成全课配音批次。样片授权仅覆盖样片，不能借此先生成整课。等待音频时可并行整理素材、设计布局与动作草图，不以旧音频或估算秒数制作需再次重映射的正式时间轴。

中途换音色：保留原动画和旧音轨，生成新音频后只更新相关镜头、媒体片段、字幕及章节边界；原字幕时间不能套用。仅缺字幕识别环境时，可按真实音频做明确标记的草稿，最终导出仍需补齐字幕。

以音频实际时间驱动画面。字幕按标点和语义切段，保存起止时间与原文对应；不要固定分成前后两半。生成完整逐字字幕时确保所有旁白有覆盖；关键词式讲解字幕应明确标注类型。

## 录制与合成

新课默认走包内 HyperFrames 路线，见 hyperframes.md：把动画放入可定位时间线，逐帧导出。已有 Canvas 录制工程继续按 runtime.md 接续，不能把旧模板作为新课的默认限制。

预加载字体、音频与图像后开始。处理音频播放失败、超时、结束事件，失败时保留可用中间产物。以批次导出并保存日志，避免一次性录全课导致失败后整片返工。批次按生产时长划分，章节按教学内容划分，两者不可混用。

HyperFrames 工程使用确定性逐帧导出。转码为目标播放器兼容格式，例如 MP4 的 H.264/AAC；分辨率、帧率和采样率使用本项目配置。

合成前明确列出当前有效分段及其顺序，不用目录通配符混入旧版、备份或损坏文件。不同分段的媒体参数/时间戳需检查，必要时先标准化再合成。章节切片依据时间轴，而非默认“一批就是一章”。

## 验收与恢复

- **源内容**：镜头数量、顺序、标题与旁白一致；示例数据有来源或标为示例。
- **声音内容**：逐镜头来源可追溯，网页/外来音频完成内容核验；复查章节开头、交接点、重做镜头，防止前章音轨重复。
- **画面**：代表帧与最长文案帧可读；无黑屏、缺字、截断、溢出、制作备注或无关浏览器界面。
- **字幕**：语义断句、换行与安全边距通过；查看第一段和最后一段，不能仅查看中间一帧。
- **媒体**：完整解码成功、有视频和音频流；总时长与时间轴相符；头中尾和各章边界同步。元数据正常不替代视觉/听感验收。
- **交付**：输出路径、版本、检查证据、用户确认状态与未决问题一致。

坏音频只重做该音频及依赖的视频；坏字幕只重做相关画面/批次；坏转码从已录 WebM 恢复。保留旧版和修复记录，不覆盖唯一可用的已确认产物。没有实际执行的检查写“未检查”，不得写“通过”。

## 章节交付与子任务

先让一个代表章节跑通配音、字幕、动画和导出，再复用已验证的样式、媒体接入及时间线写法；按教学内容设计不同动作，不把复用变成每镜同一张静态卡片。

只有宿主确实支持后台任务、且章节输入与音频时间已就绪时，才考虑并行制作独立章节。提交任务后先确认控制权已返回主任务；同步等待式调用按串行安排，不把“派了子任务”当成已有并行收益。不要求使用子代理，主任务直接制作也可以。

每个子任务有明确的章节/文件所有权，只接收该章所需资料、确定的 timing、共享风格和交付要求，不修改其他章节。禁止两个执行者同时写同一文件。主任务应先完成会阻塞所有章节的配音等共享步骤，不被第一个动画子任务的等待占住。

交付至少包含：实际动画入口路径、所用音频/字幕版本、已运行的检查及结果、未解决问题。主任务读取产物确认存在且有实质内容；只有素材骨架、空返回或口头“完成”不能算章节完成。检查已通过且输入未变更时复用记录，不重复整套检查。

空返回或无有效产物时，先检查磁盘、日志及任务状态，保留已有片段。停止同范围的旧执行者后，由主任务接管或缩小到缺失部分再分派；不能原样重派整个章节反复等待。判断卡住要看连续观察中有无有效进度，不能只凭主界面没有消息；工具调用次数与“思考中”也不能单独证明产出。

在项目现有状态文件中逐章记录：当前阶段、有效音频版本、产物路径、最后有效进度、检查结果、阻塞原因和下一步。按“配音/字幕/动画/检查/导出”分开报进度，不把网页写完报成视频完成；每完成一章或改变执行方案就更新。

## 检查与修复的结束条件

首次按 lint → check → 代表帧/播放抽查验证章节。将问题区分为：

- 必须修复：执行错误、检查零采样、黑屏/缺字/遮挡、字幕或音轨错配、丢内容、缺失教学动作、明显不同步。
- 可记录后继续：不影响功能和可读性的行数建议、代码风格提示、微小装饰差异。不能单为警告清零反复重写；警告若揭示真实内容或播放问题仍须修复。

先汇总同轮问题再集中修改，复查受影响镜头与检查；未变音频、未变章节不重跑配音、ASR或全部导出。抽样覆盖各类教学动作、长文案、起止和交接；可先看拼版定位，再看问题帧原图，存在疑问的动作要播放或查看相邻时刻。静态截图不能证明动作流畅。

默认同一问题经过两轮有针对性的修复仍未解决，就停止原样试错：保存当前文件、错误证据和失败尝试，主任务改用更简单的实现或接管定位；独立章节继续推进。两轮是改换处理方式的触发点，不是降低质量或忽略错误的许可。有新证据时可以继续针对性修复。

必要检查通过后冻结该章的输入与结果，进入导出/下一章。只有新改动、新失败或未决风险才扩大或重复检查。仍有阻断问题的章节不得标记完成或混入最终合片；其余合格章节可先输出，保留可恢复的进度。
